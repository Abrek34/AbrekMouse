# T13 — Known, intentional deviations of the local port from the official
# RawAccel reference. Rows here are expected to differ; run_oracle.sh treats
# only rows NOT in this list as drift. Format: <case-name>\t<spd>
#
# Deviation classes (five; all documented port conventions with their own tests).
# The file currently holds 79 rows and they account for exactly:
#   23 classic_gain_exp_le1 | 9 power/sync at spd 0 | 23 power_tinyexp_floor
#   | 12 p155_io_cap0_legacy | 12 p155_io_cap0_gain
# If a new row is added here, document its class in this header — an
# unexplained row reads as cruft, and the natural "cleanup" (delete it) turns
# into a hard gate failure ("UNKNOWN mismatched rows") instead of a fix.
#  1. classic *exp<=1* → the local port's "linear path" returns the constant
#     gain 1+acceleration. The official reference keeps x^(exp-1), which
#     explodes (e.g. gain ≈ 448 at speed 0.001 for exp=0.5) on the physical
#     expectation that exp<1 is an unusual config. AGENTS.md test:
#     "classic linear path (exp<=1) cap".
#     Reachability (T15/T16): the GUI spinner is bounded to [1,10]
#     (gui/ui_builder.inl `make_spin(1,10,...)`), and `sanitize_accel_args`
#     now clamps exponent_classic to [1,10] (src/config.cpp), so a real
#     daemon/GUI/CLI config can never carry exp<1 — these rows are only
#     reachable through the raw algorithm API, where the port keeps its
#     safe documented behavior.
#  2. power / synchronous at speed 0 → the port guards `x <= 0 → 1.0`
#     (identity); the reference blindly runs the formula, yielding artifacts
#     (power → 0, synchronous → ≈0.667). Speed 0 is non-physical for a mouse
#     (output = input × gain = 0 anyway). AGENTS.md test: "synchronous power<1".
#  3. power exponent_power ∈ [1e-4, 1e-3) → the port floors the shared exponent
#     at 1e-3 (BUG-02 root-cause: scale derivation and curve evaluation must use
#     the SAME n), the reference evaluates the raw ep. Every speed in the band is
#     a documented deviation; `power_tinyexp_floor` pins it (raw*_pX cases use
#     exponents ≥ 0.3 so they never exercise the band).
#  4. `p155_io_cap0_legacy` (12 rows) → `io` gain with the degenerate
#     `cap.y = 0`. The local port returns the ordinary gain curve; the
#     reference returns **0** for the whole speed range (measured:
#     ref=0 vs local 0.125893 at spd=0.001, 1 at spd=1, 7.94328 at spd=1000),
#     i.e. the reference kills all output on this input while the port does
#     not. P155.
#     The sibling family `p155_io_cap0_gain` is the SAME cap.y=0 input and the
#     SAME local result, but the reference emits **NaN** there instead of 0 —
#     measured, not assumed. Those 12 rows are NOW listed because the oracle
#     explicitly checks for finiteness mismatch (ref NaN vs local finite).
#     Do not generalise this into "cap.y=0 rows are never listed" — half of them
#     are, and those are the rows below. (AGENTS.md said exactly that and was
#     wrong; corrected.)
