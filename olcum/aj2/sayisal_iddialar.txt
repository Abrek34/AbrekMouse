# sayisal_iddialar.txt — belgedeki SAYISAL iddialarin DENETIM LISTESI
#
#   python3 olcum/aj2/prove_kod_ayni.py --sayi olcum/aj2/sayisal_iddialar.txt
#
# Format (TAB ayirici, 4 alan):
#   hedef_dosya <TAB> regex <TAB> olcum_komutu <TAB> aciklama
#
# Bu tablo bir HAKEM degil, denetlenen bir BEYANDIR: iddianin kendisi belgede
# kalir, bu dosya yalniz "bu regex'te yakalanan sayi su komutun ciktisiyla
# ayni mi" der. Elle yazilan tablo arac tarafindan olculebiliyor.
#
# Kurallar:
#   * regex TAM OLARAK 1 kez eslesmeli. 0 = dosya degismis, >1 = belirsiz; ikisi
#     de rc=2. Sessizce ilk eslesmeyi secmek YANLIS olurdu.
#   * komut stdout'u TEK sayi yazmali; cok satir yazarsa rc=2. Boylece
#     `| head` gibi boru tuzaklari sessizce gecmez.
#   * karsilastirma SAYI olarak yapilir: "100000" == "1e5" (firkati degil),
#     "3.3e16" != "3.2767e16" (bicimle gelen sapma -> kirmizi).
#   * ⭐ HASSASIYET komutun cikti bicimine baglidir. Komut `:.3g` ile 3
#     anlamli basamağa yuvarliyorsa, belgenin de ayni hassasiyeti yazmasi
#     gerekir. Asagidaki tavan iddiasi `:.3g` kullandigi icin belgede
#     `6.87e22` dogru, `68719476704000000000000` (tam yazim) kirmizidir --
#     ve bu dogru bir hukiimdur, gurultu degil: belge olcemedigi kadar
#     hassas bir sayi iddia ediyor. Komutu tam hassasiyete cevirmek bu
#     belgenin ozet yazimini da kirmizi yapardi. Ayrinti: prove_kod_ayni.py
#     icindeki run_sayi() docstring'i, ve oradaki PC-C -> PC-C' kaydi.
#
# Ayni sayinin birden fazla yerde yazilmasi BILINCLI olarak ayri ayri denetlenir:
# iki yerin ayrilmasi bir belgenin icindeki celiskiyi uretir (olculdu: once
# 1407 ve 1408, ayni dosyada).
#
# Bu liste kapsamli DEGILDIR: yalnizca denetlenmesi deger gorulen sayilar
# var. Kapsam genisletmek bir karar; her yeni iddia bir capraz referans
# denetimiyle birlikte eklenir.
#
# ============================================================================
# KASTI DENETLENMEYEN sayilar — bunlari "duzeltme"
# ============================================================================
# Asagidaki sayilar BAYAT DEGILDIR; onlar TARIHI KAYITLARDIR ve dogru
# olduklari icin guncellenmemelidir. Kayit, "bir noktada su kosul olcu" demeyi
# ifade eder; o noktadan sonra degismek kaydi YANLIS yapar.
#
#   FIX_LOG.md:519        "oracle OK (1407 satir / 67 known deviation)"
#   FIX_LOG.md:544        "oracle 1407 / 79 / 79 / OK"
#   FIX_LOG.md:607        Round-16'nin ayni satiri, alinti olarak
#   FIX_LOG.md:611        "1407 eski adin sayimdi" -- yorum, sayi iddiasi degil
#   FIX_LOG.md:617        "1407 yaziliysa exit 77" -- bir onerme, olcum degil
#   Bug Hata Raporlari.md:1867  "oracle RESULT: OK (1119 satir / 67 sapma)"
#   Bug Hata Raporlari.md:1889  "oracle RESULT: OK (1119/67) ... 34015/34015"
#
# Olculdu: bugun AGENTS.md 1408/79 ve 34164/34164 veriyor; ama o andaki
# gercek 1119/67 ve 34015/34015 idi. Bunlari 1408/34164 yapmak, bir olcum
# kaydini, hicbir zaman o olcummedigi bir sayiyi yazmis saymak olurdu.

# eski gorunur ve yalnizca olcumle ayirt edilir. Bir FIX_LOG dogrulama
# satiri "su an" demiyorsa tarihidir.
